# 短剧页面超时问题修复

## 问题描述

短剧页面（列表和详情）出现超时报错，无法正常显示内容。

## 根本原因

在 `VideoPlayerApplication.kt` 中，全局的 `OkHttpClient` 配置了**极短的超时时间**：

```kotlin
OkHttpClient.Builder()
    .connectTimeout(1500, TimeUnit.MILLISECONDS)  // 连接超时1.5秒
    .readTimeout(2000, TimeUnit.MILLISECONDS)     // 读取超时2秒
    .writeTimeout(2000, TimeUnit.MILLISECONDS)    // 写入超时2秒
    .callTimeout(2000, TimeUnit.MILLISECONDS)     // 总调用超时2秒
```

这个配置是为了**视频源快速切换**设计的：
- 当视频源无法播放时，2秒内必须响应，否则立即换源
- 这对于视频播放是合理的（快速失败，快速切换）

但是对于**短剧API请求**来说：
- 短剧API可能需要3-5秒才能响应
- 2秒超时太短，导致请求总是失败
- 用户看到的就是"超时报错"

## 解决方案

为短剧API创建**专用的 OkHttpClient**，使用更长的超时时间。

### 修改的文件

#### 1. ShortDramaViewModel.kt（短剧列表）

```kotlin
class ShortDramaViewModel(
    private val networkDataSource: NetworkDataSource = createNetworkDataSource()
) : ViewModel() {

    companion object {
        /**
         * 创建专用的NetworkDataSource，使用更长的超时时间
         */
        private fun createNetworkDataSource(): NetworkDataSource {
            val okHttpClient = okhttp3.OkHttpClient.Builder()
                .connectTimeout(10, java.util.concurrent.TimeUnit.SECONDS)  // 连接超时10秒
                .readTimeout(15, java.util.concurrent.TimeUnit.SECONDS)     // 读取超时15秒
                .writeTimeout(10, java.util.concurrent.TimeUnit.SECONDS)    // 写入超时10秒
                .callTimeout(20, java.util.concurrent.TimeUnit.SECONDS)     // 总超时20秒
                .retryOnConnectionFailure(true)  // 自动重试
                .build()
            
            return NetworkDataSource(okHttpClient, Dependencies.context)
        }
    }
}
```

#### 2. ShortDramaDetailViewModel.kt（短剧详情）

## 超时时间对比

### 全局 OkHttpClient（视频播放用）
- 连接超时：**1.5秒**
- 读取超时：**2秒**
- 总超时：**2秒**
- 目的：快速失败，快速换源

### 短剧专用 OkHttpClient
- 连接超时：**10秒**
- 读取超时：**15秒**
- 总超时：**20秒**
- 目的：给API足够的响应时间

## 为什么不修改全局超时？

### 方案A：修改全局超时（❌ 不推荐）
```kotlin
// 如果改成这样
.connectTimeout(10, TimeUnit.SECONDS)
.readTimeout(15, TimeUnit.SECONDS)
```

**问题：**
- 视频源切换会变慢（需要等待10秒才能换源）
- 用户体验变差（卡顿时间更长）
- 影响所有使用全局 OkHttpClient 的功能

### 方案B：创建专用客户端（✅ 推荐）
```kotlin
// 短剧API使用专用客户端
private fun createNetworkDataSource(): NetworkDataSource {
    val okHttpClient = OkHttpClient.Builder()
        .connectTimeout(10, TimeUnit.SECONDS)
        ...
}
```

**优点：**
- 不影响视频播放的快速换源
- 短剧API有足够的响应时间
- 各司其职，互不干扰

## 技术细节

### 依赖注入的变化

**之前：**
```kotlin
class ShortDramaViewModel(
    private val networkDataSource: NetworkDataSource = Dependencies.networkDataSource
)
```
- 使用全局的 `Dependencies.networkDataSource`
- 共享全局的 OkHttpClient（2秒超时）

**现在：**
```kotlin
class ShortDramaViewModel(
    private val networkDataSource: NetworkDataSource = createNetworkDataSource()
)
```
- 创建专用的 `NetworkDataSource`
- 使用专用的 OkHttpClient（20秒超时）

### 为什么在 companion object 中创建？

```kotlin
companion object {
    private fun createNetworkDataSource(): NetworkDataSource {
        // 创建专用客户端
    }
}
```

**原因：**
1. **单例模式**：所有 ViewModel 实例共享同一个 OkHttpClient
2. **性能优化**：避免每次创建 ViewModel 都创建新的 OkHttpClient
3. **资源管理**：OkHttpClient 内部有连接池，应该复用

- ✅ 视频嗅探（继续使用全局 OkHttpClient）
- ✅ 其他网络请求（继续使用全局 OkHttpClient）

### 受益的功能
- ✅ 短剧列表加载
- ✅ 短剧详情加载

## 性能影响

### 内存
- 增加一个 OkHttpClient 实例
- 额外内存占用：约 1-2MB
- 影响：可忽略

### 网络
- 短剧API请求时间可能稍长（但不会超时）
- 用户体验：从"超时报错"变为"正常加载"
- 影响：正面

### 电池
- 更长的超时时间可能导致更长的网络连接
- 但实际请求时间不变（只是给了更多时间）
- 影响：可忽略

## 总结

通过为短剧API创建专用的 OkHttpClient，我们解决了超时问题，同时不影响视频播放的快速换源功能。这是一个典型的"关注点分离"案例：

- **视频播放**：需要快速失败，快速换源（2秒超时）
- **短剧API**：需要稳定加载，给足时间（20秒超时）

两者互不干扰，各司其职。
