## 使用说明

### 设置下载线程数
1. 点击下载按钮
2. 在下载配置对话框中调整"多线程数"滑块
3. 设置范围：1-8个线程
4. 线程数会保存并在下载时使用

### 查看多线程进度
- 下载时会在任务下方显示分段进度条
- 每个进度条代表一个线程
- 颜色含义：
  - 🔵 蓝色：0-49%
  - 🟡 黄色：50-89%
  - 🟢 绿色：90-100%

### 自动合并 M3U8
- 应用启动时自动检查
- 或点击侧边栏"检查并合并 M3U8"按钮
- 系统会自动：
  1. 检查所有已暂停的 M3U8 任务
  2. 验证分片是否完整
  3. 合并完整的任务
  4. 显示合并结果

### 手动合并单个任务
1. 长按 M3U8 任务
2. 选择"合并 M3U8 分片"
3. 确认合并
4. 等待合并完成

### M3U8 任务状态提示
- 分片下载完成但未合并时，会显示：
  - ⚠️ 分片已下载完成，长按合并
  - 文字显示为橙色

## 技术细节

### 数据库变更
- 版本：8 → 9
- 新增字段：
  - `customHeadersJson`: 自定义请求头
  - `threadCount`: 线程数
  - `partProgressesJson`: 分段进度

### 多线程下载逻辑
1. 检查文件大小和服务器支持
2. 文件 > 10MB 且支持 Range 请求才使用多线程
3. 将文件分成 N 段（N = 线程数）
4. 每个线程下载一段
5. 下载完成后合并所有分段
6. 支持断点续传

### M3U8 合并逻辑
1. 检查临时目录是否存在
2. 验证所有分片文件
3. 按顺序合并分片
4. 验证最终文件
5. 清理临时文件

## 注意事项

1. **多线程下载**：
   - 仅对普通视频文件有效
   - M3U8 不使用多线程（已有分片机制）
   - 需要服务器支持 Range 请求

2. **M3U8 合并**：
   - 需要所有分片都下载完成
   - 临时文件在 cache 目录
   - 合并后自动清理临时文件

3. **性能考虑**：
   - 启动时延迟1秒后检查合并
   - 避免影响应用启动速度
   - 合并失败静默处理
