# Lua 到 Kotlin 转换技能包

## 简介

这是一套完整的技能包，用于将 AndroLua 项目自动转换为 Kotlin Android 项目，包括代码转换、自动构建、错误修复、测试和持续优化。

## 技能列表

### 1. master-lua-kotlin.md (主技能)
整合所有功能的主技能，提供完整的转换工作流程。

**使用方法**: 
```
请使用 master-lua-kotlin 技能将 androlua源码/main.lua 转换为 Kotlin
```

### 2. lua-to-kotlin-workflow.md
Lua 到 Kotlin 的核心转换规则，包括语法、类型、函数、布局等转换。

**包含内容**:
- 导入语句转换
- 变量声明转换
- 函数定义转换
- 表/对象转换
- 布局转换
- 回调函数转换
- 字符串操作转换
- 数组/列表转换
- 条件语句转换
- 循环转换

### 3. android-layout-conversion.md
Android 布局专项转换技能，处理 AndroLua 的布局 DSL。

**包含内容**:
- LinearLayout 转换
- CardView 转换
- TextView 转换
- ImageView 转换
- TabLayout 转换
- RecyclerView 转换
- 布局参数映射
- 颜色处理
- View Binding 使用

### 4. log-analysis-fix.md

## 自动化 Hook

### auto-build-install
当 Kotlin 文件保存后，自动执行构建、安装和测试。

**触发条件**: 保存 .kt 文件
**执行动作**: 
1. 构建项目
2. 分析错误日志
3. 自动修复错误
4. 安装到设备
5. 查看运行日志
6. 修复运行时问题

## 使用指南

### 快速开始

1. **转换单个文件**
   ```
   请将 androlua源码/main.lua 转换为 Kotlin
   ```

2. **转换整个项目**
   ```
   请将 androlua源码 目录下的所有 Lua 文件转换为 Kotlin 项目
   ```

3. **构建和测试**
   ```
   请构建项目并安装到设备测试
   ```

4. **分析和修复错误**
   ```
   请分析构建错误并自动修复
   ```

### 高级用法

1. **自定义转换规则**
   编辑 `lua-to-kotlin-workflow.md`，添加新的转换模式。

2. **添加错误修复规则**
   编辑 `log-analysis-fix.md`，添加新的错误识别和修复规则。

3. **优化布局转换**
   编辑 `android-layout-conversion.md`，优化布局转换逻辑。

## 工作流程示例

### 完整转换流程

```
用户: 请将 androlua源码/main.lua 转换为 Kotlin 并测试

AI 执行:
1. 读取 androlua源码/main.lua
2. 应用转换规则生成 Kotlin 代码
3. 保存到 app/src/main/java/com/tv/ball/MainActivity.kt
4. 运行 ./gradlew assembleDebug
5. 检查编译错误
6. 自动修复错误
7. 重新构建
8. 运行 ./gradlew installDebug
9. 启动应用
10. 监控运行日志
11. 报告结果

AI 回复:
转换完成！
- 生成文件: MainActivity.kt
- 构建状态: 成功
- 安装状态: 成功
- 运行状态: 正常
- 发现问题: 0 个
```

### 错误修复流程

```
用户: 构建失败了，请修复

AI 执行:
1. 读取 .kotlin/errors/*.log
2. 分析错误类型
3. 应用修复规则
4. 修改代码
5. 重新构建
6. 验证修复

AI 回复:
已修复 3 个错误:
1. 添加缺失的导入语句
2. 修正类型转换
3. 添加空安全检查

重新构建成功！
```

## 反馈和改进

如果转换结果不理想:

1. 告诉我具体问题
2. 我会分析原因
3. 更新转换规则
4. 重新转换验证

例如:
```
转换后的布局显示不正确，原始 Lua 代码是这样的...
```

## 技能组合

可以组合使用多个技能:

```
请使用 lua-to-kotlin-workflow 和 android-layout-conversion 技能
转换这个包含复杂布局的 Lua 文件
```

## 注意事项

1. **首次转换**: 可能需要多次迭代才能完全正确
2. **复杂布局**: 可能需要手动调整
3. **第三方库**: 需要手动添加依赖
4. **自定义组件**: 可能需要重新实现
